Build a full-stack web application called **LeetCode Tracker**.

## Goal

Create a website where users can enter their LeetCode username and phone number. The application should periodically check the user's LeetCode profile/submissions and detect when a new problem has been solved. Whenever a new accepted submission is detected, send a WhatsApp notification to the registered phone number.

The application should be designed as a real, deployable project and should use free-tier services wherever possible.

## Important Requirements

- Use only free/open-source technologies and free tiers.
- The application must be deployable.
- Do not use paid services unless absolutely required for WhatsApp messaging.
- Keep the architecture simple, scalable, and beginner-friendly.
- Do not over-engineer the project.
- Use environment variables for all API keys, tokens, database credentials, and secrets.
- Never expose secrets in frontend code.
- Write clean, modular, production-quality code.
- Explain important implementation decisions.
- Provide setup instructions after completing each major stage.

# 4. Submission Tracking

The backend must periodically check the user's recent LeetCode submissions.

Use the most appropriate publicly accessible LeetCode data/API mechanism available.

Important:

- Do not aggressively scrape LeetCode.
- Respect rate limits.
- Only request the minimum amount of information required.
- Handle API failures gracefully.
- Do not assume an undocumented endpoint will always remain available.
- Isolate the LeetCode data-fetching logic into its own service/module so it can easily be replaced later.

The system should identify:

- Submission ID
- Problem name
- Problem slug
- Difficulty
- Language
- Submission status
- Submission timestamp

Only an **Accepted** submission should trigger the WhatsApp notification.

---

# 5. New Problem Detection

The most important functionality:

The system must remember the user's previously processed submissions.

Example:

Previous submission:

submission_id = 12345

Next check:

submission_id = 12346

If submission 12346 is an accepted solution that has not been processed before:

1. Store it in the database.
2. Mark it as processed.
3. Send WhatsApp notification.

Do NOT send duplicate notifications for the same submission.

The system must remain idempotent.

---

# 6. WhatsApp Notification

When a new accepted problem is detected, send:

🎉 New LeetCode Problem Solved!

Problem: Two Sum
Difficulty: Easy
Language: C++
Status: Accepted

Keep the notification concise.

Use Meta WhatsApp Cloud API where possible.

Store WhatsApp credentials only in backend environment variables.

Never expose:

- Access tokens
- API keys
- Phone number IDs
- Database credentials

to the frontend.

If WhatsApp API setup requires paid usage or is unavailable during development, implement a notification abstraction so Telegram/email can be used for testing without changing the core tracking system.

# 8. Scheduled Job

Use Cloudflare Cron Triggers.

Example:

Every 10 minutes:

1. Fetch active users.
2. Fetch recent submissions for each user.
3. Compare with stored submissions.
4. Detect new accepted submissions.
5. Save new submissions.
6. Send notification.
7. Mark notification as sent.
8. Log errors.

Make the interval configurable.

Do not hard-code secrets or sensitive information.

# 10. Error Handling

Handle:

- Invalid LeetCode username
- LeetCode unavailable
- API timeout
- Rate limiting
- Supabase failure
- WhatsApp API failure
- Invalid phone number
- Duplicate submission
- Duplicate notification
- Missing environment variables

The application should fail gracefully.

If WhatsApp fails, do not lose the submission record.

Instead:

- Save the submission.
- Mark notification_sent = false.
- Retry later.
